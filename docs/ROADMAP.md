# 후속 개발 우선순위

아래는 아직 완료되지 않은 개발 계획이다. 시연 UI를 건드리기 전에 실제 과제 범위와 연결 권한을 확인한다.

| 순서 | 목표 | 완료 판단 | 지침 / 3+1 |
| --- | --- | --- | --- |
| 1 | 서버 궤적 저장소·역할·동의·감사 | 두 클라이언트가 같은 trajectory_id를 읽고 서버가 잘못된 승인/발송을 거부 | 2·4·6 / 온톨로지·Human in the loop |
| 2 | IRS+·검진·웨어러블·EMR 어댑터 | 원본·단위·시간·출처·중복·결측을 검증하고 같은 선에 연결 | 1·3·6 / 온톨로지 |
| 3 | Flutter 환자 앱과 의료진 웹 | W 질문→의사 판단→환자 전달의 실제 계정 흐름 | 2·3·4 / Human in the loop |
| 4 | M3 초기 이탈 순 선 묶음·승인 개입 | 대체 원인·책임 의료진·확인 범위·발송/응답/관찰이 추적됨 | 1·4·5 / JITAI·Human in the loop |
| 5 | 판단 후보와 수정 이력·회귀 평가 | 후보 정책이 재생 평가와 의료진 승인을 거쳐 버전화 | 4·6 / 재귀적 자기개선 |
| 6 | 기관 설정 한 개·설치 한 명령 | 깨끗한 환경에서 설정·권한·백업·어댑터를 포함해 재현 | 1·5·6 / 운영 기반 |

## 비스타·제주 검토 목록

IRS+ 환자 노출, 의료진 유전체 보조참고, 기관 분석 IRB·협약, 연구군 본인 동의, 가족의 선, 습관 시뮬레이션, 자동개입 범위를 검토 목록으로 유지한다. 국가·기관별 플래그는 검토 상태를 표현할 뿐 허가를 대신하지 않는다. 회색지대 기능은 삭제 대신 별도 검토 경로로 남긴다.

## 실증 지표

- 안정성: 연속 경험 완주율, 오류/중복/누락, 복원 성공, 지연과 프레임시간.
- 수용성: 신뢰 전후 설문과 응답률, 확인된 행동 이행률, 의사 수정/기각률과 보류율 분리.
- 재무: 환자당 검토 시간·운영비·시간당 관리 인원, 실제 비용·매출 근거. 클릭 수로 절감액을 추정하지 않는다.

금지 패턴 점검은 매 기능마다 한다. 점수 카드·EMR 요약·센서 타일·별도 관리 포털·LLM으로 감싼 기존 기능으로 돌아가지 않고 같은 궤적의 판단과 다음 한 걸음을 유지한다.
