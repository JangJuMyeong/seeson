# 궤적과 권한

Trajectory는 person_id·trajectory_id·version·consent_refs·node_ids·layer_versions를 가진다. Node는 type·occurred_at·recorded_at·actor·source_refs·evidence_refs·context_refs·status·supersedes·trace_id를 가진다. 측정/질문/의사확인/이탈/개입/선택/결과를 구분하고 정정은 덮어쓰지 않고 연결한다.

IRS+·두 기준선·온톨로지·로그가 동일 trajectory_id를 참조한다. 임상 사실·사용자 진술·AI 가설·예측을 구별한다. 예측에는 모델 버전·입력 노드·가정·시점·불확실성이 필요하다. 부정·가족력·과거 질환을 현재 본인의 확진으로 승격하지 않는다.

온톨로지 관계에는 subject/predicate/object/source/valid_from/valid_to/asserted_by/verification_status가 있다. 야간근무·돌봄·측정 가능 시간·개인 목표는 동의와 출처를 가진 맥락이다. 측정 누락은 기기 장애·입원·휴식·거절과 구별하여 평가한다.

## 발화와 개입

- 첫 W: 기록과 IRS+ 관리 우선순위, 출처 있는 일반 지침. AI 개인 진단 금지.
- M1: 적절한 역할의 의사가 특정 항목을 확인/수정. confirmation_id·clinician_id·시점·scope·유효/재검토 조건 기록.
- 이후 W: ‘[의사]가 [시점]에 [질환]으로 확인한 기록입니다’와 원 확인 노드. 취소·정정 시 현행 표시와 개입 재평가.
- M3: 근거·책임 의료진·유효한 확인/승인 프로토콜·동의·추적 로그가 갖춰져야 발송. Yes/No·미응답·결과를 별도로 기록. 확인 범위 밖의 개입 강도 상승 금지.

실제 서비스의 권한은 서버에서 확인하고 중복 발송 방지·아웃박스·재시도·승인 만료/취소 처리를 둔다. UI 버튼 숨기기로 대체하지 않는다.

| 종류 | 문구 기준 |
| --- | --- |
| 금지 개인 판정 | ‘당신은 고혈압 전단계입니다’처럼 AI가 미확인 개인 질환을 단정 |
| 기록 관찰 | ‘최근 기록에 측정이 없는 구간이 있습니다’와 원 데이터 |
| 지침 설명 | ‘[기관]의 [연도/제목]은 [조건]을 [내용]으로 설명합니다’와 확인한 출처; 개인에게 자동 적용 금지 |
| 확정 전달 | 의사·시점·질환·확인 노드를 연결 |
| 시연 | ‘가상 선택 시나리오 · 실제 건강 예측이 아닙니다’ |

수치 기준·질환 정의는 최신 일차 출처를 확인한다. 출처를 꾸며 내지 않는다. 이 문구 정책은 법률·인허가 판정이 아니다.

환자 Flutter와 의사·워드 웹이 같은 저장소를 쓴다. IRS+, SiBC, iCHMS, OCR, Samsung Health, EMR은 어댑터다. 원본·단위·검사/수신 시점·신뢰도와 중복 방지를 보존한다. W–M1–M3부터 완주하되 M2 확장을 막지 않는다.
